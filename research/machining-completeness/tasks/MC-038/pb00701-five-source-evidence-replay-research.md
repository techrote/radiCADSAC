## Problem and hypothesis

The historical frozen V54 121-source corpus classifies 20 source-route cases as \`BLOCKED\` and another 30 multi-span sources as \`BLOCKED:SPAN_OWNER_LACKS_EXACT_ORDERED_SPAN_PREMISE\`. Since v54, three source-specific proof producers have landed separately with valid provenance but different record representations:

- [PR #323](https://github.com/techrote/radiCADSAC/pull/323): one actual V27-refused V6 tail100 source has a unique true source-knot touching root with separate one-sided orders;
- [PR #326](https://github.com/techrote/radiCADSAC/pull/326): three other distinct original-source V27 refusals, including a harvested source endpoint root and two V8 tails, with explicit rational source roots and tangencies/crossings;
- [PR #330](https://github.com/techrote/radiCADSAC/pull/330): one V43-refused original V9 tail100 source, with exactly one simple implicit physical root in the strict rational bracket (1/4,1/3).

The hypothesis is that these **five and only these five** already-established original-source mathematical results can be replayed from their exact pinned generating code and source certificates, then **losslessly normalized** into one conservative source-ID-keyed event/sign interface. Normalization does not supply a missing general theorem or arbitrary source-root decider; it must never promote incomplete counts, unverified algebraic coordinates, unbound user reports, or original v54 route refusals.

The result specifically combines the five *distinct original source records*. Equal mathematical root coordinates in the V8 tail0 and tail100 sources do **not** represent the same manufacturing history, body, journal or physical event and may not be merged across source records.

## Normalized physical event contract

Every admitted source view has one immutable original source ID/hash/phase/interval, its literal historical V54 route-refusal reason, complete source-ordered physical events, strict span and whole-source root counts, and maximal physical sign cells. Each event uses exactly one of:

- \`RATIONAL\` original source coordinate, with exact fraction such as \`0\`, \`1/2\`, \`1\`, \`3/2\`;
- \`IMPLICIT_STRICT_BRACKET\` with exact disjoint rational bounds and an explicit generating **source-specific uniqueness theorem**, **not** a fabricated rational/algebraic root coordinate.

Physical locations are distinguished as \`SOURCE_LEFT_ENDPOINT\`, \`SPAN_OPEN\`, and \`SOURCE_KNOT\`; a source endpoint contributes to the **closed** root count but **not** the strict source-interior count; a source knot contributes to the whole-source strict-interior count exactly once, but to neither adjacent *span-open* count. A zero at the true source knot retains left/right one-sided vanishing orders and signs; **no global smooth multiplicity is invented**. The source-knot physical coordinate and every span boundary must match actual original B-spline source knots.

A finite structural validator rejects out-of-order/overlapping root brackets, omitted/duplicate roots, false endpoint versus knot localization, wrong span counts, zero-order/one-sided-order confusion, crossing with equal signs, tangency with unequal signs and incompatible maximal open sign cells. Its finite allowlist hard-codes the qualified case shapes, so an arbitrary newly submitted source cannot inherit completeness from these examples. The same validation is applied after independent replay, not merely on a caller-declared \`PASS\`.
