## The highest-value common theorem seam: semantics vs live authority

**Proposed verification separation, not a novel theorem:** a valid mathematical result certificate is not a grant to reuse it in a current mutable solver session. A prospective consumer should independently establish **all** of:

1. **Source custody:** independently replay the original typed producer object, verify full source and spline knots/controls, explicit phase units/coordinates, schema, data hashes, and exact producing head; never trust a caller-provided origin hash or a syntactically valid envelope alone.
2. **Semantic equivalence:** establish the mathematical equivalence/order/sign rule on its *stated* domain, including sided knots and identity-zero cases; neither a point root nor a germ proves the complete partition.
3. **Current authority:** current World generation, epoch, applied material/variant policy, signed-IN capability, worker fence, Rapier body/contact sample and exclusive owner must be checked at the *consuming boundary*; historical receipts are distinct from fresh authorization.
4. **Complete dynamic dependencies:** all relevant radius/phase, gas component/pressure, source/sink, actor movement, reaction, parcel handoff and rollback edges must be tracked, or return `UNKNOWN/RECOMPUTE`.
5. **Runtime admission:** actual same-law native physical hash/quantity/worker parity, low tracking overhead, same-host A/B/B/A, median/tail, memory/allocation and quiescence/wake checks; hybrid law differences must use explicit tolerances rather than fabricated exact parity.

This is a conjunction of classical dependency-completeness and source-authorization conditions. An additive proof-receipt *description* might bridge A1/A2/B1 and B2/B3, but no implementation should run per cell until stage-specific work avoidance is measured.

### Source-critical B3 replay witness (reported independently by B4; rechecked against current source)

In [`handoff_contract.py` at `90a410f`](https://github.com/techrote/cybersand/blob/90a410f43b7d74cea7b8189b7bb283b66ea70be5/research/solver-certificates/handoff/handoff_contract.py), `commit` calls `fp = intent.fingerprint()` and then checks `if intent.token in w.accepted`, returning a previous receipt with `status="IDEMPOTENT"` **before** the `if not fenced`, generation, current epoch and source-revision checks. A successful transfer itself advances `w.epoch`; replaying the same token with `fenced=False` after that transfer therefore returns an *old successful-receipt payload* marked `IDEMPOTENT`, not `BAD_FENCE` or `STALE_EPOCH`.

This is **not a second mutation or a mass-conservation counterexample**; idempotent historical responses may be deliberate. The exact contract gap is at a prospective downstream consumer: treating `IDEMPOTENT` (or old `water_after`) as proof of a *currently fenced, epoch-valid* handoff would be unsound. A B3 consumer contract must classify these as **HISTORICAL_ACK_ONLY**, never current authority. Test: accepted transfer -> advance epoch -> replay identical token with fence false -> assert no state change, historical-only status, *cannot* authorize new parcel insertion/force/contact. Also test generation and policy change. Do not weaken true idempotency or introduce native changes.

**Separate cost-accounting caution:** the same B3 source calls `water_total` and `water_momentum_q256` before and after transfer, copies `dict(w.records)`, and validates full-state invariants. The `bound_cost_model(...)["full_world_scans_added"] == 0` test is an **idealized proposed production accounting target**, not an execution measurement. It must never be cited as an achieved O(1) prototype property. B3's README already acknowledges O(N) model costs.
