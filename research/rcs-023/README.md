# RCS-023 — propagated uncertainty and error-budget algebra

Status: deterministic research implementation for issue #42.  
Model: `rcs-uncertainty-budget/1.0`.

## Purpose

This package turns the RCS-007/DR-0010 separation of tolerance and uncertainty channels into executable propagation rules. It does **not** introduce a programme-wide epsilon and does not treat manufacturing tolerance as numerical-error allowance.

The model is deliberately representation/provider neutral. It records bounded uncertainty from canonicalization, trajectory fitting, frame transforms, tool-envelope derivation, provider execution, fallback representation and reconciliation while retaining programme-owned journal/revision/body provenance.

## Default algebra

Unknown or potentially correlated bounded errors compose by conservative interval/Minkowski sum. Each stage remains attached to its downstream sensitivity; stage errors may not be detached and re-summed after nonlinear/scale-changing transformations.

RSS is available only as a diagnostic helper and requires explicit independence evidence. Proven cancellation is narrower still: it requires evidence that terms derive from the same bounded source with known coefficients. A provider handoff carries **source residual + conversion residual + destination residual** rather than replacing the source error with the destination error.

Manufacturing requirement, contact policy and export validation are non-error policy channels. The implementation rejects attempts to add them as numeric error contributions.

## Decision semantics

`model.py` implements these programme statuses:

- `decisively_no_material_change` only when the whole physical interval proves clearance/no interaction or a durable semantic retrace proof exists;
- `decisively_positive_material_change` only when the entire interval proves positive physical change;
- `bounded_representation_inexact` for bounded fallback state that still requires B-rep reconciliation;
- `accepted_pending` when the decision boundary lies inside the uncertainty interval;
- `error_budget_breach` for a known propagated bound beyond the requested budget;
- `refused_accuracy_unproven` for unknown required error or incomplete reconciliation;
- `export_eligible` only after complete bounded reconciliation inside the applicable RCS-005 geometric budgets.

Explicit positive-removal commands have an additional invariant: if their feature interval overlaps zero, they remain `accepted_pending`; they do not silently become no-ops.

## Measured deterministic campaign

`reference-results-v1.json` is generated by `run_campaign.py` and is checked byte-semantically by CI. The campaign contains representative lathe and mill end-to-end traces plus the required adversarial/boundary probes.

The committed reference produces:

- lathe full-pipeline final half-width: **14.5 nm**, export eligible under the fixture's 20 nm dimension/surface budget;
- mill fallback full-pipeline final half-width: **17.5 nm**, with an explicit `bounded_representation_inexact` state before B-rep reconciliation and export eligibility only afterward;
- contact sweep with **10 nm** uncertainty: `-10 nm`, exact tangent and `+10 nm` remain pending; only the `±20 nm` witnesses are decisive;
- **1 nm** positive-removal command under **5 nm** uncertainty: pending with signed positive intent preserved;
- 100 correlated **1 nm** errors: conservative/same-sign witness **100 nm** versus an unsafe RSS diagnostic of **10 nm**;
- provider handoff: 8 nm source + 6 nm conversion + 4 nm destination = **18 nm** conservative bound; max-only accounting would report only 8 nm;
- order-sensitive transform witness: **45 nm** versus **30 nm** depending on which unequal local source occurs before a ×2 downstream gain;
- reconciliation controls: 15 nm passes a 20 nm budget, 26 nm breaches it, and an unmeasured fit refuses despite its known component being only 3 nm.

These are research fixtures used to exercise the algebra; they are not production default tolerances.

## RCS-005 / STEP mapping

RCS-005 remains authoritative for STEP success. This prototype's scalar spatial bound is suitable only for the applicable dimension/surface comparison path. RCS-005 volume and angular channels remain separate unless a geometry-specific sensitivity proof maps upstream errors into those metrics.

A STEP/export claim therefore requires all of the following:

1. every required numerical/representation channel has a demonstrated bound;
2. no local contact/positive-intent ambiguity relevant to committed geometry remains unresolved;
3. fallback/deferred representation has reconciled to conventional B-rep;
4. the final propagated geometric bound fits each applicable requested RCS-005 dimension/surface budget;
5. all independent RCS-005 topology/body/analytic/unit/read-back gates still pass;
6. RCS-022's independent interoperability state remains truthful (`interoperability_unqualified` until separately qualified).

A large manufacturing tolerance never substitutes for an unknown provider/reconciliation bound.

## RCS-018 / RCS-025 integration guidance

RCS-018/RCS-025 coordinator traces should carry this budget trace as derived execution evidence tied to durable journal/revision/body semantic IDs. Provider-private topology/process identity remains forbidden from durable state.

Recommended coordinator mapping:

- decisive one-sided material result → ordinary accepted material result;
- uncertainty interval crossing a decision boundary → `accepted_pending` with signed intent and trace retained;
- bounded fallback before conventional B-rep → `accepted_pending` plus `bounded_representation_inexact` representation detail;
- known budget breach → non-success/error-budget status; do not heal or widen tolerance;
- unknown required bound/incomplete reconciliation → refusal for exact/export paths;
- provider handoff → append source, conversion and destination residuals; never reset the budget at the boundary.

RCS-025 should preserve and extend the same trace through each defer/reconcile/provider transition and make remaining budget an explicit handoff precondition.

## Reproduction

From the repository root:

```bash
python3 -m py_compile research/rcs-023/*.py
python3 -m unittest discover -s research/rcs-023 -p 'test_*.py' -v
python3 research/rcs-023/run_campaign.py \
  --out-dir .results/rcs023 \
  --compare-reference research/rcs-023/reference-results-v1.json
python3 tools/validate_rcs023.py --results-dir .results/rcs023
```

The campaign and tests use only Python's standard library.
